# 密码学选型速查表（Crypto Cheatsheet）

> module-18-bouncy-castle 配套的选型速查文档：从「要解决什么问题」出发给算法选型与对照。
> 完整演示代码见 `module-18-bouncy-castle` 各 Demo 类，算法清单与核心概念见该模块 README。
> 配套文档：[网络协议选型速查表](network-cheatsheet.md)（module-15）。

## 0. 三问选型法

1. **要解决什么问题？** 机密性（加密）/ 完整性（防篡改）/ 认证（来源可信）/ 不可否认（签名）。
2. **合规约束？** 是否要求国密 SM2/SM3/SM4（金融 / 政务 / 等保密评）。
3. **运行环境？** 密钥长度限制、有无 AES 硬件加速、设备算力与存储。

## 1. HMAC vs CMAC（重点对照）

| 维度 | HMAC | CMAC |
|---|---|---|
| 构造 | 哈希 + 密钥 `H(key⊕opad ‖ H(key⊕ipad ‖ msg))` | 分组密码（AES）构造（NIST SP 800-38B，= OMAC1） |
| 依赖原语 | 哈希函数（SHA-256/SHA-512 等） | 分组密码（AES/DES/SM4） |
| 标签长度 | = 哈希输出（32 / 64 字节） | = 分组大小（AES = 16 字节） |
| 抗长度扩展 | 是（密钥参与计算） | 不适用（非哈希构造） |
| 软件实现 | 简单、平台普遍支持、快 | 需分组密码；有 AES-NI 硬件时同样快 |
| 典型场景 | API 签名（HMAC-SHA256）、JWT(HS256)、HOTP/TOTP 动态口令、TLS 记录层 | 智能卡 / 嵌入式（已有 AES 硬件、无哈希依赖）、受限设备协议（SCTP 等） |
| 怎么选 | 服务端/网络场景：密钥是共享秘密，双端都能算 | 已有分组密码原语、带宽/存储敏感（短标签）、不能引入哈希 |

**决策规则：**
- 已有共享密钥，要「防篡改 + 认证」→ **HMAC**（除非受限环境）。
- 环境已有 AES 硬件加速 / 智能卡，不想引入哈希依赖 → **CMAC**。
- 标签越短越好（省带宽/存储）→ **CMAC**（16 字节）；无所谓 → HMAC（32/64 字节更稳）。

## 2. 哈希选型

| 算法 | 摘要长度 | 安全状态 | 用途 |
|---|---|---|---|
| MD5 | 16 字节 | 已破（碰撞） | 仅非安全校验 / 兼容 |
| SHA-1 | 20 字节 | 已破（碰撞，SHAttered） | 仅兼容遗留 |
| SHA-256 | 32 字节 | 安全 | **通用默认** |
| SHA-3(256) | 32 字节 | 安全（Keccak，结构独立于 SHA-2） | 新系统选型 / 防御纵深 |
| SM3 | 32 字节 | 安全（国密） | 国密合规系统 |

**决策规则：** 默认 SHA-256；**密码存储用加盐 + 慢哈希（BCrypt/Argon2）**，不是裸 SHA-256；国密场景用 SM3；MD5/SHA-1 不做任何安全相关计算。

## 3. 对称加密选型（AES 模式）

| 模式 | 认证 | 填充 | 注意 | 用途 |
|---|---|---|---|---|
| GCM | ✅ AEAD | 无 | IV 12 字节随机、标签 16 字节 | **默认首选**：TLS、数据库字段、文件 |
| CBC | ❌ | PKCS7 | 需随机 IV；**可被块翻转攻击精确篡改** | 遗留（必须另配 MAC） |
| CTR | ❌ | 无（流式） | **IV 严禁重复** | 磁盘/存储加密（配合 HMAC） |
| ECB | ❌ | PKCS7 | 相同明文块 → 相同密文块 | **禁用** |

**决策规则：** 一律用 **GCM**（认证加密，防篡改一次搞定）；CBC/CTR 仅在兼容遗留且另配 MAC 时使用；ECB 禁用。

**国密对称：** 用 **SM4**（128 位分组/密钥，对标 AES-128），同样 GCM 优先。**DES/3DES** 仅遗留兼容（旧金融 / 读卡器 EMV 过渡），新系统一律 AES/SM4。

## 4. 非对称 / 签名选型

| 算法 | 类型 | 密钥长度 | 用途 |
|---|---|---|---|
| RSA | 加密 / 签名 | 2048~4096 位 | 证书体系、密钥封装分发、代码签名；明文长度受限（2048+OAEP-SHA256 上限 190 字节） |
| ECC（P-256） | 协商 / 签名 | 256 位 ≈ RSA-3072 | TLS 证书与密钥交换、区块链、IoT（密钥短、计算快） |
| Ed25519 | 签名 | 32 字节 | **现代签名首选**：快、密钥小、抗侧信道、实现不易出错 |
| DSA | 签名 | 2048 位 | 遗留政府标准，不推荐 |
| SM2 | 加密 / 签名（国密） | 256 位（sm2p256v1） | 国密 PKI、金融身份认证、电子签章（GB/T 32918） |

**关键区分：**
- **签名**（不可否认）：私钥签名、公钥验签 → 完整性 + 认证 + 不可否认。
- **加密**：公钥加密、私钥解密 → 机密性。
- **大块数据**：非对称只加密对称密钥（混合加密 / 数字信封），数据本身用对称加密（快）。

## 5. 密钥协商

| 算法 | 安全性依赖 | 用途 |
|---|---|---|
| DH-2048 | 离散对数 | 遗留 / 兼容 |
| ECDH（P-256） | 椭圆曲线离散对数 | **默认**：TLS ECDHE、端到端加密（Signal 等） |

**注意：** 协商结果只是共享秘密，还需经 KDF（如 HKDF）派生会话密钥；公钥交换要防中间人（配证书 / 签名认证）。

## 6. 国密合规组合（SM2 + SM3 + SM4）

```
发送方: SM4 加密数据 → SM2 加密 SM4 密钥 → SM3 摘要 → SM2 签名
接收方: SM2 解密钥 → SM4 解数据 → SM3 重算摘要 → SM2 验签
```

适用：等保 / 密评、金融政务合规数据传输（对称加密大块数据、非对称安全分发密钥、签名保证完整性与不可否认）。

## 7. 证书与密钥库

| 组件 | 用途 |
|---|---|
| X.509 证书 | 公钥绑定身份 + 信任链（CA 签发、有效期、SAN 域名）——HTTPS、代码签名、S/MIME |
| PKCS#12（.p12/.pfx） | 私钥 + 证书链打包容器，整体口令保护——TLS 服务器密钥库、浏览器导入、代码签名分发 |

## 8. 一分钟决策速查

| 需求 | 选 |
|---|---|
| 校验文件没坏 | SHA-256 |
| 存储密码 | 加盐 + BCrypt/Argon2（慢哈希） |
| 网络/字段传输加密 | AES-GCM（国密场景 SM4-GCM） |
| API 签名（共享密钥） | HMAC-SHA256 |
| API 签名（非对称/不可否认） | Ed25519（国密 SM3withSM2） |
| 受限设备消息认证 | AES-CMAC |
| 双方协商会话密钥 | ECDH（P-256） |
| 大块数据加密 + 密钥分发 | 混合加密：对称加密数据 + 非对称包密钥 |
| HTTPS 服务器证书 | X.509 + PKCS#12 |
